# How to Fill Out the Weekly Status Report

Use this file as a guide when completing the weekly status report template in `template.md`.

## 1. Update the report header

At the top of the document, fill in:

- Report Date: the date the report covers
- Prepared By: your name or team
- Team / Program: the area being reported on

## 2. Write a concise executive summary

Provide a short overview of the week in 3-5 bullet points:

- Overall status this week
- Key accomplishments
- Main risks or blockers
- Dependencies requiring attention

Keep this section brief and leadership-friendly.

## 3. Capture completed work

Use the "Work Completed This Week" section to list what was finished.

Recommended columns:

- ID: task or work item ID
- Task: task title
- Owner: responsible person or team
- Status: use Completed, In Progress, Blocked, or Not Started
- Due Date: target or actual completion date
- Notes: brief details of the result or impact

## 4. Record current work status

In the "In Progress / Blocked / Not Started" section, add work items that are still active or not yet started.

Include:

- The current status
- Any barriers or delays
- The next action needed

## 5. Track milestones

Use the "Milestones" section to show progress against important program milestones.

For each milestone, capture:

- Name
- Target date
- Current status
- Completion percentage
- Any notes about schedule or scope changes

## 6. Surface risks and blockers

List any issues that could affect delivery, quality, or schedule.

Include:

- Item description
- Owner
- Severity
- Impact
- Mitigation or next action

## 7. Document dependencies and handoffs

Dependencies often need stakeholder attention. Record them in the "Dependencies and Handoffs" section.

For each dependency, note:

- What depends on whom
- Current status
- Action required
- Due date

## 8. Add next week priorities

Summarize the three to five most important actions for the next reporting period.

This section should help leadership quickly understand what comes next.

## 9. Note decisions needed or escalations

If any item needs executive support, approval, or intervention, record it in this section.

## 10. Tips for a strong report

- Be specific and factual, not overly verbose
- Use consistent statuses across all work items
- Highlight blockers early
- Focus on actions, ownership, and decisions needed
- Use the example file as a reference for tone and structure

## 11. Suggested status values

You can use these values to keep reporting consistent:

- Completed
- In Progress
- Blocked
- Not Started
- On Track
- At Risk
- Delayed
